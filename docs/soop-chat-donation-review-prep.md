# SOOP Chat SDK 후원 연동 심사 사전 준비

상태: **1차 Consent 심사 반려 / 재심사 준비 중 / 실제 SOOP 연결 비활성**

## 1. 제공하려는 기능

인증 스트리머가 자신의 SOOP 방송에 온이유 게임을 연동하면, 게임의 의상 선택 화면이 열려 있는 동안 시청자 한 명이 별풍선 50개 이상을 한 번에 후원했을 때 꾸민 의상을 자동으로 확정한다.

- 대상은 스트리머 본인이 인증한 방송국만이다.
- 기존 인증 스트리머와 SOOP 동의 계정이 동일하다는 점을 검증할 수 있을 때만 연결한다. 닉네임·프로필이나 `user_stationinfo`를 고정 계정 식별자로 사용하지 않는다. 검증 방법이 확인되지 않으면 연결을 활성화하지 않는다.
- 의상 선택 화면이 닫혀 있거나 이미 확정된 뒤의 후원은 의상 선택에 사용하지 않는다.
- `count >= 50`인 단일 LIVE 후원 이벤트만 처리하고, `fromVod`가 `true`이거나 누락된 이벤트는 제외한다.
- 여러 사람의 누적 후원이나 후원자의 닉네임·프로필을 조건으로 사용하지 않는다.
- 이 연동은 기존 Firebase 로그인·Google·Kakao 로그인·스트리머 인증을 대체하거나 계정과 연결하지 않는다.

## 2. SOOP 심사에 제출할 설명

> 인증 스트리머가 본인 방송에서 진행하는 인터랙티브 게임 ‘당신이 여기에 온 이유’에서, 시청자의 별풍선 후원 이벤트를 실시간으로 수신합니다. 한 번에 50개 이상 후원된 경우에만 방송 중 열린 의상 선택 화면의 꾸민 의상을 자동 확정합니다. 계정 통합 로그인이나 시청자 식별·프로필 수집에는 사용하지 않으며, 스트리머 본인이 연동을 승인하고 언제든 해제할 수 있습니다.

신청 범위는 후원 이벤트 수신에 필요한 Chat SDK Consent 권한으로 한정한다. SOOP가 고정 사용자 식별자를 제공하지 않는 현재 상태에서는 OAuth를 공통 로그인이나 기존 Firebase 계정 연결에 사용하지 않는다.

## 3. 심사 제출물 체크리스트

- 서비스명, 서비스 URL, 앱 로고
- HTTPS Redirect URI와 운영 서버 도메인
- 이용약관·개인정보 처리방침 URL
- 인증 스트리머가 새 게임·이어하기·챕터 불러오기로 진입하기 전에 확인하는 필수 준비 동의 화면: 거절 시 게임을 시작하지 않으며, 보관 항목·24시간 만료·철회 방법과 심사 승인 뒤 별도 SOOP 동의를 받는다는 점을 명시
- 모의 후원 시연 화면: 필수 안내 동의 → 의상 선택 대기 → 49개는 미확정, VOD 이벤트는 제외, LIVE 50개 이상은 자동 확정, 같은 세션의 중복 전달은 무시
- 모의 시연은 SOOP 로그인·토큰·채팅·실제 후원 이벤트를 사용하지 않는다는 고지
- 최소 권한 요청 사유 및 후원 이벤트 외 사용하지 않는다는 설명

## 4. 승인 뒤 구현 기준

1. 인증 스트리머만 연동을 시작할 수 있고, 서버가 `streamerVerifications`의 인증 SOOP ID를 다시 확인한다.
2. 스트리머가 별도 SOOP 동의를 완료하면 authorization code를 서버에서 교환한다. 갱신 토큰은 Secret Manager에 최대 24시간 저장하고, SDK가 쓰는 접근 토큰은 게임 브라우저 메모리에만 전달한다.
3. 게임이 의상 선택을 열 때만 짧은 수명의 활성 세션을 서버에 등록한다.
4. `BALLOON_GIFTED` 이벤트가 `count >= 50`이고 `fromVod === false`이며 활성 세션이 미처리 상태일 때만 서버 RTDB transaction으로 원자적으로 한 번 확정한다. 수량·이벤트 원문·후원자 정보는 저장하지 않고, 세션 상태와 확정 시각만 기록한다. SOOP 답변에 따르면 Chat SDK는 인증한 스트리머 본인의 방송에 연결된다.
5. 브라우저는 열린 본인 세션에서 SDK 이벤트를 확인하고, 세션이 소비되면 `chosenOutfits[chapterId]`를 꾸민 의상으로 설정한다.
6. VOD·다시보기 이벤트와 만료된 세션은 무시한다. 여러 소켓 연결로 같은 이벤트가 중복 전달될 수 있으므로, 활성 의상 세션은 최초 기준 충족 이벤트에서 한 번만 소비한다. 이벤트 고유 ID에 의존하지 않는다.
7. SOOP 권한 철회/연동 해제가 확인되면 SDK `disconnect()`를 호출하고 재연결을 멈춘 뒤, 브라우저 메모리 접근 토큰과 서버 갱신 토큰을 삭제한다.

현재 설계의 한계: Chat SDK 이벤트는 브라우저에서 수신되고, 서버에는 브라우저가 전달한 세션 ID·`count`·LIVE 여부만 도착한다. 서버 transaction은 같은 세션의 중복 확정을 막지만, SOOP가 서버 검증용 서명이나 신뢰 가능한 서버 콜백을 제공하지 않는다면 후원 발생 자체를 서버에서 독립 검증하지 못한다. 이 연동은 의상이라는 게임 내 선택만 바꾸며 캐시·이용권·유료 권한을 지급하지 않는다. SOOP 제출/실사용 전 이 한계를 확인하고, 더 가치 있는 혜택에 사용하지 않는다.

현재 공개 데모(`soop-donation-demo.html`)는 모의 이벤트만으로 위 임계값 흐름을 설명한다. 실제 앱은 인증 스트리머의 모든 게임 진입에 사전 준비 동의가 필요하지만, 이 동의는 준비 데이터에만 적용되며 심사 전엔 후원 감지와 자동 의상 선택을 활성화하지 않는다. SOOP 승인 후 실제 OAuth/Chat SDK 연결을 구현할 때 이 구분을 유지하고, 승인된 실제 권한과 동의 화면을 다시 검증한다.

## 5. 개인정보 최소화 및 보관 원칙

- 후원자의 닉네임, 프로필 이미지, 채팅 내용은 저장하지 않는다.
- 현재 사전 준비 동의 기록에는 인증 스트리머 UID, 인증 SOOP ID·닉네임, 동의 상태·시각, 갱신 시각, 만료 시각만 둔다. 서버 전용 RTDB 경로에 저장하며 동의할 때 해당 기록의 24시간 만료 시각에 실행할 일회성 삭제 작업을 예약한다. 동의 철회 시 기록을 즉시 삭제하며 철회 이력은 남기지 않는다. 동의가 없을 때 계속 실행되는 정리 스케줄은 두지 않는다.
- 의상 선택 세션은 승인 후 실제 연동이 활성화된 뒤에만 만들며 10분 후 만료한다. 브라우저 게이트와 서버 transaction이 각각 중복 확정을 막는다. 확정 시 서버에는 상태와 확정 시각만 잠시 기록하고 게임이 세션을 닫으면 즉시 지운다. 닫기 요청이 실패하면 등록 시 예약한 일회성 만료 작업이 삭제를 시도하며, 일시적 작업 실패 시 재시도 때문에 실제 삭제가 늦어질 수 있다.
- SOOP 문서상 `BALLOON_GIFTED` 이벤트에는 `userId`, `userNickname`, `count` 등이 포함되며 고유 이벤트 ID는 문서에서 확인되지 않았다. 실제 활성화 전에 SOOP에 중복·재전송 동작과 공식 토큰 폐기 방법을 확인한다.
- 후원 이벤트 원문, 후원자 식별 필드, 후원 수량은 저장하지 않는다. 서버에는 현재 의상 선택 세션의 UID, 검증된 방송 ID, 챕터, 상태, 생성·만료 시각만 저장하며 확정된 경우 확정 시각을 추가한다. 확정 시 게임이 닫기 요청을 보내 즉시 삭제하며, 미확정 또는 닫기 실패 세션은 10분 만료 시점에 예약 작업이 정리한다. 일시적인 작업 실패 시 재시도되어 실제 삭제가 늦어질 수 있다.
- 심사 승인 전에는 OAuth 토큰·실시간 채팅·후원 이벤트를 수집하지 않는다. 아래 토큰·이벤트 처리 설계가 구현과 일치하는지 기능 활성화 전 검증한다.

## 6. 실제 연동의 토큰·이벤트 처리 설계

아래 정책은 SOOP Chat SDK Consent 심사 승인 뒤, 실제 기능을 켜기 전에 구현·검증할 기준이다. 현재 프로덕션은 심사 준비 동의 정보만 처리하며 실제 SOOP OAuth 토큰·후원 이벤트는 받지 않는다.

- Chat SDK OAuth authorization code는 서버에서 교환한다. SOOP Client Secret은 Firebase Functions Secret Parameter로만 공급하며 브라우저 번들, URL, RTDB, 로그에 넣지 않는다.
- `refresh_token`은 UID별 Secret Manager 항목에 보관한다. 보관 상한은 동의 시각부터 24시간이며, 해당 UID의 Functions 실행 서비스 계정만 읽을 수 있게 최소 권한을 준다. 관리자 화면과 앱에는 토큰 원문을 반환하지 않는다.
- Access Token 만료는 SOOP 응답의 `expires_in`을 기준으로 관리한다. 만료 시점에 맞춘 일회성 갱신 작업을 현재 유효한 실제 연동 동의와 저장 토큰이 있을 때만 예약하고, 갱신 성공 시 다음 만료 작업을 예약한다. 유효한 연동이 없으면 상시 갱신 작업은 실행하지 않는다. SOOP가 권한 철회/연동 해제를 나타내는 갱신 오류를 반환하면 SDK `disconnect()` 후 재연결을 중지하고 서버 토큰을 삭제한다. 네트워크 일시 오류는 권한 철회로 오인하지 않는다.
- `access_token`은 SDK의 `setAuth(access_token)`/`connect()`에 필요하므로 게임이 열린 브라우저 메모리에만 전달한다. `localStorage`, `sessionStorage`, URL, RTDB 및 로그에는 저장하지 않는다. 게임 탭 종료·채팅 연결 해제 때 메모리 참조를 제거한다.
- 연동 해제, SOOP 권한 철회 확인, 인증 UID 탈퇴, 24시간 만료가 발생하면 새 토큰 발급을 막고 연결·활성 세션을 종료한 뒤 Secret Manager의 UID별 토큰을 삭제한다. SOOP가 공식 토큰 폐기 API를 제공하는지 확인해 지원될 경우 서버 사본 삭제와 함께 호출한다. 폐기 API 지원 여부가 확인되기 전에는 심사용 설명에서 SOOP 측 폐기까지 완료된다고 약속하지 않는다.
- 후원 이벤트는 게임 메모리에서 `count`와 `fromVod`만 의상 선택 조건으로 사용한다. Chat SDK가 인증한 스트리머 본인의 방송에 연결하고, `fromVod === false`인 단일 이벤트가 50개 이상일 때만 현재 의상 세션을 한 번 확정한다. `userId`, `userNickname`, `imageUrl`, 채팅 원문은 저장하지 않는다. 이벤트 원문과 이벤트 분석 이력도 보관하지 않는다.
- 서버 세션에는 Firebase UID, 검증된 방송 ID, 챕터, 상태, 시작·만료 시각만 둔다. 확정된 경우 확정 시각도 일시 저장한다. 의상 확정·해제 때 즉시 지우고, 남은 세션은 10분 만료 시점의 예약 작업이 삭제한다. 작업이 실패하면 재시도 때문에 삭제 시각이 늦어질 수 있다.
- 2026-11-02 SOOP Developers 회신: Access Token 만료 시간은 `expires_in`으로 확인하고 Refresh Token으로 갱신한다. 연동 해제는 실시간 통지가 어려우므로 갱신 응답에서 해제를 확인하면 SDK를 `disconnect()`하고 토큰을 삭제·재연결 중지한다. 여러 채팅 소켓 연결로 중복 이벤트가 올 수 있고, 게임에서 이미 확정된 의상이 재처리되지 않도록 해야 한다. 50개 이상 여부는 `count >= 50`, LIVE만 적용할 때는 `fromVod`를 확인한다.
- SOOP 회신으로 Refresh Token의 만료·교체 규칙은 확정되지 않았다. 심사 설명에는 우리 서비스의 최대 24시간 보관 상한을 구분해 적고, 공급자 토큰의 실제 만료·회전 규칙은 확인 전까지 단정하지 않는다.
- SOOP는 고정 `user_id`/`sub`를 제공하지 않으며 `user_stationinfo`를 로그인 계정 연결 식별자로 쓰지 말라고 안내했다. 실제 활성화 전에는 OAuth 동의 계정과 기존 인증 스트리머 방송이 동일한지 닉네임·프로필에 기대지 않고 검증 가능한지 확인해야 한다. 이를 입증할 수 없으면 실제 연결을 켜지 않는다.

이 내용을 반영해 개인정보 처리방침의 실제 연동 보관·접근·삭제 항목을 명시했다. 실제 기능을 활성화하기 전에는 Secret Manager 권한, 토큰 만료·삭제 재시도, 연동 해제, 브라우저 메모리 폐기, 49개/50개 경계, 중복 전달을 테스트하고 결과가 정책과 일치하는지 다시 확인한다.
